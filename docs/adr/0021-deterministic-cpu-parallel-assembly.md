# ADR-0021：显式线程数的确定性 CPU 单元装配

**状态：** 已接受，等待 ABI 1.3 三平台验收

## 背景

T3/T4 C++20 体积装配已经显著快于可读有限元参考实现，但仍是单线程。直接使用
硬件并发数会使 Agent 无法提前预算资源，也可能在工作站和服务进程中造成过度
订阅。对全局载荷数组直接使用原子加法又会改变归约顺序、降低可重复性。

## 决策

1. ABI 1.3 新增 T3/T4 并行入口，不修改 ABI 1.0–1.2 的已有函数；
2. `thread_count` 由调用方显式给出，默认生产行为仍为一个线程；
3. 单元使用连续静态分块，各线程写互不重叠的 COO 区间；
4. 节点载荷使用线程私有缓冲区，并按固定线程编号归并；
5. 计划摘要绑定线程数和额外临时内存，执行前可由 Agent 预算拒绝；
6. 不使用 OpenMP、TBB 或平台专属线程池；第一阶段只依赖 C++20 标准线程；
7. 不在本次并行 CSR SpMV。其当前单次耗时很小，必须先证明收益再增加复杂度。

## 后果

- COO 数组在所有线程数下保持完全相同；载荷允许舍入级差异，但同一线程数必须
  可重复；
- 临时内存随 `线程数 × 向量 DOF` 增长，计划层必须诚实报告；
- 显式线程数便于 AgentFEM 控制资源并避免嵌套并行；
- ABI 提升要求一次完整 Tier-1 验收，普通 Linux 快检不能替代 Windows/macOS
  证据；
- 若代表规模上多线程没有实际收益，自动生产选择继续保持单线程，接口仍可用于
  后续预构建图和数值回填阶段。
