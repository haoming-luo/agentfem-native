# ADR-0030：用 Kernel Contract 0.3 接入限定 T3 线性动力学

- 状态：接受
- 日期：2026-09-20

## 背景

Gate 3 线性动力主干已经具备质量装配、显式/隐式积分、稳定预检、零位移约束、
能量与外力功账本、反力和确定性重启，但 AgentFEM 的版本化 JSON 边界仍停留在
0.2 静力。直接暴露 Python 内部对象会使 AgentFEM 依赖 Native 的可变实现细节，
也会绕开现有资源计划、预算和证据收据。

## 决策

发布向后兼容的 Kernel Contract 0.3：

1. 0.1 热传导和 0.2 静力请求继续按原版本解释；0.3 成为新的默认版本。
2. 0.3 接纳二维 T3、无阻尼、零位移固定约束的线性瞬态固体力学。
3. 请求使用网格、材料、密度、静态载荷形状、标量分段线性载荷曲线、时间步、
   步数、积分方法和初始状态，不接纳预装配矩阵或第三方有限元对象。
4. 显式方法强制集中质量；Newmark 可选择一致或集中质量。
5. 最后接受状态以带 SHA-256 的检查点返回，并可作为后续请求的重启输入。
6. JSON 资源预算和调用方传入的取消/进度上下文统一经过 `ExecutionContext`；失败
   使用稳定错误码、路径、可重试标志和修复建议。
7. 结果返回自由度历史、能量/功账本、约束反力、计划摘要和执行证据；历史输出
   的峰值内存必须在执行前计划中保守计入。

## 范围边界

0.3 不包含阻尼、非零或时变位移约束、T4 动力学、自适应时间步、非线性、MPI、
GPU 或时间序列 VTK。分段线性载荷曲线必须覆盖本次执行的完整绝对时间区间，
禁止静默外推。检查点只保存算法状态，不保存提供者缓存或预条件器对象。

## 理由

该设计让 AgentFEM 通过稳定、可移植的数据边界调用 Native 自主有限元语义，
同时保留先规划、再授权执行、最后审查证据的智能体安全流程。载荷采用“自主装配
的空间载荷向量 × 标量时间曲线”，足以覆盖当前验证范围，又避免提前引入通用
表达式系统或把 AF-IR 变成内核依赖。

## 后果

- 0.3 的动力能力在三平台 Gate 候选通过前保持 `implemented`；源提交 `a630793`
  后续通过完整 Tier-1 `35482705887`，仅验收矩阵限定的 T3 范围晋级为
  `verified`。
- 契约请求、结果 Schema、可运行示例、定向测试和来源记录必须同步维护。
- 后续阻尼、非零约束功和更复杂载荷需要新规格与兼容扩展，不能改变 0.3 语义。
