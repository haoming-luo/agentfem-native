# ADR-0026：用 Kernel Contract 0.2 接入 T3/T4 线性力学

- 状态：接受
- 日期：2026-09-20

## 背景

自主 T3/T4、稀疏求解、资源规划和执行收据已经存在，但 AgentFEM 能稳定调用的
JSON 契约仍只覆盖热传导。若直接让 AgentFEM 依赖 Python 问题类或当前 AF-IR，
会把产品对象变化传入内核，并形成绕过资源预检和证据边界的第二条执行路径。

## 决策

发布向后兼容的 Kernel Contract 0.2：

1. 保留 0.1 热传导协议及 Schema；0.2 是新的默认版本。
2. 0.2 增加 T3/T4 线性静力学的可移植数据表达。
3. JSON 请求只负责降级为 Native 已拥有的网格、材料、边界条件和过程对象。
4. 公开预检入口复用现有 `ExecutionPlan`；正式执行复用 `execute_plan`。
5. 结果绑定规范请求摘要、计划摘要和执行证据摘要，显式返回成熟度。
6. AF-IR 适配仍是外部薄适配，不成为 Native 里程碑主线。

## 理由

这条路径直接服务 AgentFEM 的智能体安全计算：先判断能力和资源，再执行已接受
的计划，最后返回可追踪结果。它复用自主有限元语义，不复制求解逻辑；同时保持
提供者可替换、平台中立和 JSON 可移植。

## 后果

- AgentFEM 可以在不导入 Native 私有对象的情况下规划和执行 T3/T4。
- 0.1 调用方无需同步升级。
- 契约扩展必须同步更新规格、Schema、定向测试和来源记录。
- 本 ADR 接受时力学成熟度为 `implemented`；随后源提交 `654fe02` 在完整 Tier-1
  运行 `35461748299` 关闭 G2-01 至 G2-12，T3/T4 基础线性静力范围已按验证政策
  提升为 `verified`。
- 非线性、动力学、MPI 和 GPU 不因接口可扩展而提前进入生产契约。
