# ADR-0027：预备力学装配不再重复生成 COO 行列索引

**状态：** 已接受；ABI 1.5 三平台验收通过

## 背景

`CSRAssemblyPlan` 已经拥有固定单元 DOF 顺序、规范 CSR 图和每个局部贡献到 CSR
槽位的映射，但当前 T3/T4 预备路径仍调用普通 C++ 装配，重复分配和写入 COO
`rows/columns/data`，随后只消费 `data`。对 T3 每个贡献临时占 24 字节，其中 16
字节是已由计划确定的索引；T4 同理。这与 AgentFEM 显式持有执行计划、避免重复
符号工作的产品方向不一致。

## 决策

1. ABI 1.5 允许现有串行 T3/T4 装配入口在 `rows` 和 `columns` 同时为空时只写
   按单元—局部行—局部列排序的数值贡献与载荷；只有一个索引指针为空仍失败；
2. Python Stable ABI 增加仅数值入口，公开包装只分配 `data/load`；
3. 已准备且选择串行 native 路径的 T3/T4 直接使用仅数值入口，再通过计划的既有
   确定性映射回填 CSR；普通 COO API 和所有旧 ABI 调用保持不变；
4. 多线程预备装配暂时沿用原路径。共享 CSR 的并发归并、线程私有数值缓冲或
   图着色必须另立规格，不能借本增量改变浮点归并次序；
5. 数值贡献、载荷、最终 CSR、解和证据必须与旧路径一致；内存声明只计算明确
   消除的两份 `int64` COO 索引，不外推为端到端峰值。

## 后果

- 串行预备 T3/T4 每次装配避免 `16 × contribution_count` 字节的临时索引；
- 仍保留一个完整局部贡献数组和 `coo_to_csr` 映射，因此这不是最终的元素直写
  CSR，也不宣称 P3 已完成；
- ABI 次版本提升要求严格 C/C++、Stable ABI、科学差分和完整 Tier-1 三平台验收；
- AgentFEM 继续显式拥有计划，Native 不引入进程全局缓存或第三方有限元语义。

Windows/Linux/macOS Tier-1 验收。该证据接纳实现的平台边界，不改变“P3 尚未
完成、性能不跨平台外推”的结论。
