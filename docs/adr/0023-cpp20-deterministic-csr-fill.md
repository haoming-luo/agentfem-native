# ADR-0023：用 C++20 按原贡献顺序回填 CSR 数值

**状态：** 已接受，ABI 1.4 生产候选

## 背景

`CSRPattern` 已把一次性的符号排序与重复数值更新分离，本地证据表明回填阶段远快
于每次重新规范化 COO。现有 `numpy.add.at` 是清晰的数学参考，但重复 T3/T4
装配需要一个不依赖 SciPy/PETSc 的生产回填路径。

## 决策

ABI 1.4 新增最小 C++20 数值回填入口。它不拥有稀疏图生成语义，只消费 Native
已验证的 `coo_to_csr` 映射；先完整校验，再按原 COO 贡献顺序串行累加。Python
保留独立 `fill_reference`，非空生产图通过 ABI 回填，空图仍由参考边界处理。

本增量不引入原子加法、图着色、线程私有 CSR 缓冲或求解器。它们会改变内存、
浮点次序或并发错误面，必须分别规格化和测量。

## 后果

- 重复装配可绕过 Python 高开销的索引归约，同时保持逐位确定性；
- ABI 发生兼容版本提升，必须重新执行 Windows、Linux、macOS 完整验收；
- 映射仍占用一个 `int64` 数组，且元素内核目前仍产生 COO 数值；
- 后续优化必须以端到端 T3/T4 收益为准，不能只报告孤立回填倍率。
