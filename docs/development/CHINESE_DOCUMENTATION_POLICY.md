# 中文工程表达规范

**状态：** 已采用  
**生效日期：** 2026-09-13

## 目标

AgentFEM Native 的重要设计、数学含义和计算边界必须首先让中文使用者与
维护者准确理解。中文不是发布后的附加翻译，而是项目的主要工程表达语言。

## 必须使用中文的内容

- README、路线图、项目介绍、架构说明、ADR、数学规格、验证报告和已知限制；
- 公开 Python API 的重要文档字符串，以及类、函数和模块的用途说明；
- 解释数学公式、索引约定、状态迁移、所有权、线程安全、数值稳定性和性能取舍
  的重要代码注释；
- 面向人的警告、错误说明、运行摘要、能力说明和 Agent 解释文本；
- 新增测试中对物理场景、数学恒等式和失败原因的说明。

## 保留英文的稳定技术边界

为了保持跨平台互操作性，以下内容使用清晰、稳定的英文或 ASCII 标识；其面向
人的解释必须使用中文：

- Python/C/C++ 标识符、包名、命令行选项和环境变量；
- JSON 字段、Schema 标识、ABI 名称、稳定错误码和机器可解析枚举；
- 数学符号、标准单位符号、文件格式名和第三方项目专有名称；
- 外部接口明确要求的原文许可证和版权声明。

例如，稳定错误码可以是 `solver.nonconvergence`，但其 `message`、诊断和安全
修复建议应为中文。不得为了中文化而破坏已经发布的序列化契约或 ABI。

## 注释质量

注释重点解释“为什么、数学含义、边界和风险”，不逐行复述代码。高性能代码
必须说明：

- 数据布局和循环顺序为什么这样选择；
- 哪些不变量使并行、向量化或缓存优化仍然正确；
- 与可读 NumPy 基准层如何对应；
- 浮点归约顺序、可重复性模式和允许差异的证据边界。

## 迁移规则

新内容从现在起遵守本规范。已有英文文档和注释按“触及即迁移”的方式逐步
改为中文；数学规格、验证记录和来源声明不得机械批量翻译。每次迁移都应保留
提交号、运行号、数值和引用的原始含义。可以安排独立的文档迁移批次，但不得
让翻译工作阻塞当前科学里程碑。

代码评审需要检查中文说明是否准确，同时检查稳定英文标识是否保持兼容。
