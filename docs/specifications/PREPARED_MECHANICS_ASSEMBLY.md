# 预备力学稀疏装配规格 0.1

**状态：** 0.1 已实现；0.2 无重复 COO 索引路径进入 ABI 1.5 候选

## AgentFEM 使用场景

AgentFEM 的多载荷工况、材料参数扫描、线性动力时间步和未来 Newton 迭代通常在
固定网格拓扑及 DOF 编号上重复生成矩阵。Native 必须允许执行计划复用稀疏图，
并在拓扑变化时可靠拒绝旧计划，避免 Agent 静默复用错误的矩阵结构。

## 契约

`CSRAssemblyPlan` 由非负 `dof_count` 和二维 `cell_dofs` 一次构造。它拥有只读的
单元 DOF 快照与 `CSRPattern`，并公开稳定图摘要、局部尺寸、单元数、贡献数、
CSR 非零数和内存量。

`fill(values)` 只接受形状为 `(cell_count, local_size, local_size)` 或等长一维、
有限 binary64 的贡献，保持单元—局部行—局部列顺序，返回共享只读图的新
`CSRMatrix`。`validate_layout` 要求 DOF 总数和单元 DOF 表逐项相同。

T3/T4 的预备装配入口必须先用当前问题重建 DOF 表并验证计划，再执行既有已接纳
元素路径，最后只把数值交给计划回填。冷、预备两条路径的矩阵图和数值必须完全
一致，载荷与 DOF 映射不变。

## 求解提供者

线性代数提供者接受 `COOMatrix | CSRMatrix`。自有提供者不得把已规范 CSR 再转回
COO；NumPy 小问题基准使用共同 `to_dense`；可选 SciPy 使用 CSR 三数组构造。
提供者仍不拥有有限元拓扑、元素或约束语义。

## 失败与成熟度

无效 DOF、空局部尺寸、形状错误、非有限贡献或布局失配必须在返回矩阵前失败。
0.1 不承诺缓存元素矩阵、预条件器分析、约束图、直接元素到 CSR 或并行回填。
只有端到端性能、完整本地证据与平台 CI 通过后，才可把状态改为已实现。

## 0.2 串行 native 仅数值装配

计划已经固定单元 DOF 顺序时，串行 C++ T3/T4 装配不得再次生成 COO 行列索引。
它只返回与原 COO `data` 完全同序的有限 binary64 数值贡献和同一载荷向量；计划
继续按 `coo_to_csr` 的原贡献顺序确定性回填。普通未准备路径仍返回完整 COO，
两条路径的贡献、载荷和最终 CSR 必须逐位一致。

ABI 1.5 通过现有串行入口的成对空 `rows/columns` 表达仅数值模式。二者必须同时
为空或同时有效；只有一个为空返回状态 1。仅数值模式不适用于当前并行入口，也
不改变旧调用方的缓冲区布局和输出。

明确减少的临时内存为：

```text
avoided_coo_index_bytes = 2 * contribution_count * sizeof(int64)
```

该数值不包含贡献数组、计划映射、CSR 结果、载荷、材料、求解器工作区和 Python
对象头，不能冒充进程 RSS 或端到端内存降幅。下一阶段是否直接写 CSR，必须先为
并发归并顺序、失败原子性和真实峰值内存建立独立规格与证据。
